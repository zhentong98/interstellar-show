# Interstellar Show — 设计文档

## 目标

做一个网页版的"现场演出"：一个乐团在 3D 音乐厅的舞台上演奏星际穿越对接场景的配乐，
舞台后方的巨幕播放对接片段。核心标准只有一个：**震撼**。

## 音源策略（双模式）

| 模式 | 音源 | 用途 | 乐手动画驱动 |
|---|---|---|---|
| **公开模式**（默认，GitHub Pages） | 巨幕上的 YouTube 嵌入（ID 见 `src/songs.js`），声音来自片段本身 | 分享给别人看 | Cue 时间表（按 `player.getCurrentTime()` 触发） |
| **本地模式**（仅自己电脑） | 用户自己放在 `media/` 下的视频/音频文件 | 自己爽 | Web Audio `AnalyserNode` 实时频谱 + Cue 时间表 |

- `media/` 已加入 `.gitignore`，**任何受版权保护的音视频都不得提交到仓库**。
- 本地模式检测方式：页面启动时 `fetch('media/docking.mp4', {method:'HEAD'})`，
  存在就用本地 `<video>` 作为巨幕并接入 Web Audio；否则回退到 YouTube。
  也支持把文件拖进页面加载（`URL.createObjectURL`）。
- 可额外叠加一层**原创**的 Web Audio 效果（超低频嗡鸣、冲击 hit），
  不得合成或模仿原曲旋律。

## 视觉：Three.js 3D 音乐厅

- **舞台**：深色音乐厅，巨大的管风琴音管墙位于舞台后方两侧，中央是巨幕。
- **巨幕**：播放电影原片片段。公开模式用 `CSS3DRenderer` 把 YouTube iframe 放进 3D 空间，
  与 WebGL 场景共享相机；本地模式直接用 `VideoTexture`（可加 bloom 发光）。
- **乐团：追求写实**（参考真实交响音乐会的现场照片，而不是游戏风格）
  - 中央：管风琴手坐在巨大的教堂式管风琴控制台前（致敬原声在伦敦 Temple Church 录制）
  - 左侧：弦乐组（小提琴、大提琴，拉弓动作）
  - 右后方：合唱团（黑色礼服，整体随乐句呼吸起伏）
  - 前排：定音鼓（高潮时重击）
  - 指挥正前方偏右：木管两排台阶（长笛、双簧管在前，单簧管、大管在后）；大提琴后方：圆号；左后角：两架三角钢琴
    （按原声编制缩编：原声是 34 人弦乐、24 人木管、4 架钢琴、60 人合唱，铜管只用了圆号）
  - **人物**：带骨骼绑定的写实人体模型 + 动作捕捉动画（Mixamo 等），
    每个乐手的动画加随机相位和速度偏移，避免整齐划一的"机器人感"
  - **乐器**：PBR 材质的写实模型（木纹、铜管、金属音管的反射）
  - **写实的关键在灯光**：真实音乐会的舞台本身偏暗，靠追光和轮廓光塑造人物。
    这样既显得真实，又能遮住实时渲染人物的恐怖谷问题；镜头也不要推到人脸特写
- **光效**：HDRI 环境光 + 舞台追光（SpotLight 投射阴影）、体积光柱与薄雾、
  UnrealBloomPass、ACES 色调映射、高潮时的白光爆闪和镜头轻微震动。
  星尘粒子只在巨幕周围点缀，不要盖过写实感。

## 演奏同步：乐手必须"真的在弹"

目标：每一次击鼓、每一次换弓、每一次按键都对上音乐里真实的音符，不是循环播放的动画。

### 演奏轨（performance track）

每段曲目有一个 `src/performance/<slug>.json`，记录从音频中分析出的**数值特征**（不含任何音频）：

- `beats`：节拍时间点（给指挥用）
- `onsets`：按频段分组的起音时间点：低频→定音鼓、中频→弦乐、人声频段→合唱
- `notes`：管风琴的音符事件 `{t, dur, pitch, velocity}`（音高转写，如 basic-pitch）
- `energy`：各频段能量包络，30Hz 采样
- `offset`：音频与 YouTube 片段的时间对齐偏移

**演奏轨的来源（按优先级）**：

1. **标签页音频录制（推荐，不需要下载任何文件）**：隐藏的"录制模式"
   `?record=<slug>` 用 `getDisplayMedia({ audio: true, preferCurrentTab: true })`
   抓取本页正在播放的音频，在浏览器里实时分析（Web Audio + Meyda 做特征，basic-pitch 的 TF.js 版做音高），
   播放完导出 JSON。每段只需录一次，提交 JSON 后所有观众都用这份数据。
2. 本地 `media/<slug>.mp4`（用户用自己合法拥有的文件，例如正版数字版切出的片段）：
   `scripts/analyze.py` 离线分析，可先用 Demucs 分离声部再分别检测，精度更高。

### 预读（lookahead）是真实感的来源

演奏轨是事先算好的，所以每个动作都可以**提前准备**，和真人演奏者一样：

- 定音鼓手在击打前约 150ms 抬起鼓槌，击中瞬间鼓皮振动、镜头轻微震动
- 弦乐在 onset 处换弓方向，弓速与中频能量成正比，左手揉弦
- 管风琴手的双手用 IK 按到**对应音高的琴键**上，低音用脚踩踏板；琴键和音管随音符亮起
- 合唱团在乐句开始前吸气（胸腔起伏），嘴型开合跟随人声频段能量
- **指挥**站在舞台中央前方，按 `beats` 画出拍子图形，重拍前有预备拍。指挥是"整个乐团真的在演"的最强信号

每个乐手的反应时间和动作幅度都加个体差异（±20ms、±15%），后排乐手动作更小。

### 编制与导播

- 编制要大：约 40 人弦乐、木管 8 人、圆号 4 支、钢琴 2 架、30 人合唱、4 架定音鼓、管风琴和指挥。前排用完整骨骼加 IK，后排用 InstancedMesh 和较轻的动画
- 镜头规则见下方"镜头：看电影的感觉"，导播切镜只在电影座位视角之外作为可选模式
- YouTube `getCurrentTime()` 更新不连续，每帧用 `performance.now()` 在两次读数之间插值，保证动作不抖

## 镜头：看电影的感觉

参考真实的**电影交响音乐会（Live to Picture）**：巨大银幕放电影，乐团在银幕下方现场演奏。

- 视频在**同一页面内**播放，嵌在 3D 音乐厅的巨幕上，不跳转、不弹出 YouTube
- **电影座位视角（默认）**：片段播放时，镜头固定在观众席正中偏后的"最佳座位"，
  巨幕占画面约 70%，比例接近 IMAX 影厅；乐团在画面下方三分之一，由舞台灯光勾勒，
  灯光不能打到银幕上（真实场馆会严格控制溢光）
- 片段播放时镜头**几乎不动**，只有极缓慢的呼吸式漂移；高潮时轻微震动。
  看电影时镜头乱切会破坏沉浸感
- 换场、开场、谢幕时镜头才自由移动：推近乐团、扫过管风琴音管墙、回到座位
- **导播模式（可选开关）**：在重要音符前切到乐器特写，每次不超过 2 秒，
  构图必须让巨幕留在背景里，画面里始终有电影
- 巨幕比例跟随片段（16:9 或 2.39:1 遮幅），四周用黑色吸光幕布包边

### 巨幕的渲染层次（技术关键）

YouTube iframe 只能以 DOM 形式存在（`CSS3DRenderer`），WebGL 画不进去。
为了让前景的乐团、指挥、观众剪影能**挡在银幕前面**：

- CSS3D 层放在最底层，WebGL canvas 叠在上面并使用透明背景
- 在银幕位置放一块与 iframe 完全重合的 WebGL 平面，材质用 `NoBlending` + 透明色，
  在 WebGL 画面上"挖一个洞"露出下面的视频；这块平面参与深度测试，
  所以站在银幕前的人物会正常遮住视频
- iframe 是真实的 DOM 视频，画面清晰度和原片一致，不会因为贴图而变糊
- 本地模式直接用 `VideoTexture`，没有这个限制，还可以给银幕加轻微的 bloom 溢光

## 选歌：观众自己点

曲目数据在 `src/songs.js`（YouTube ID 已核实，不要改动或凭记忆新增）。

- **选歌界面做成一张音乐会节目单**：纸质质感、衬线字体，列出 5 首曲目和对应的电影场景，
  观众勾选想听的歌（可多选，默认全选），按原顺序组成本场的 setlist
- 点"开场"按钮开始演出，这一下同时解锁浏览器的有声播放限制
- 演出中可以唤出一个低调的底部控制条：跳到下一首、结束演出
- 曲目之间：灯光转暗，乐手放下乐器，舞台侧的字幕牌显示下一首的曲名
- 每一首都是**电影原片片段**（优先 Paramount Movies 官方频道），巨幕直接播放片段，
  声音是电影原声（配乐 + 音效 + 对白）
- 节目单上标注每段的来源频道；`official: false` 的片段要标"非官方上传"
- **曲间换场**时巨幕显示自绘的黑洞 Gargantua 引力透镜 shader，配合舞台灯光转暗
- 本地模式按 slug 找文件：`media/<slug>.mp4`

## 演出流程：像真的坐在音乐厅里

核心原则：**按下"入场"之后，观众不需要再碰任何东西**，从第一首自动演到最后一首，
中间所有环节都按真实音乐会的礼仪进行。控制条默认隐藏，只有鼠标移到底部才出现。

### 1. 入场（开演前）
- 节目单页的按钮叫"入场"。点击后进入全屏，隐藏鼠标，同时解锁有声播放
- 视角是**观众席第 8 排**：画面下方有前排观众后脑勺的剪影，偶尔有人低头、侧身
- 观众席灯亮着，满场低声交谈（环境音），乐手陆续上台落座，翻开谱子
- 首席小提琴起立，双簧管给出 A 音，全团**调音**（用 Web Audio 原创合成）

### 2. 开演
- 观众席灯光逐排熄灭，交谈声渐弱到安静
- 指挥从侧台走上来，**全场鼓掌**，指挥和首席握手，向观众鞠躬
- 指挥转身、举起指挥棒，全场静止约 2 秒，这一刻巨幕亮起，第一段开始

### 3. 曲目之间
- 片段结束后，指挥手势收住，停顿一拍才放下指挥棒
- **掌声**（强度随上一首的 intensity 峰值变化，No Time for Caution 之后最热烈）
- 乐手放下乐器、翻谱，零星有人咳嗽，观众低声交流
- 舞台侧字幕牌亮出下一首的曲名，巨幕换成黑洞 Gargantua 过渡
- 换场期间**预加载下一段视频**（`cueVideoById`），保证指挥举棒后立刻开始，不出现缓冲
- 换场总长约 15 到 25 秒，节奏不拖

### 4. 终场
- 最后一段结束，指挥双手停在空中，几秒的寂静后掌声爆发
- 观众起立（前排剪影站起来），乐团起立，指挥谢幕，示意各声部起立致意
- 指挥下台、再上台返场鞠躬一次，观众席灯光渐亮
- 最后显示节目单背面：本场曲目、片段来源、CREDITS

### 声音素材
- 掌声、交谈、咳嗽：使用 CC0 录音（如 Freesound 上标注 CC0 的素材，登记到 CREDITS.md），或用 Web Audio 程序化合成
- 调音：Web Audio 原创合成，A = 440Hz

### YouTube 的沉浸感陷阱（必须处理）
- 播放器参数：`controls=0`、`rel=0`、`disablekb=1`、`playsinline=1`、`iv_load_policy=3`
- **片段结束前约 0.5 秒就切走**（渐黑或换成 Gargantua），不让 YouTube 的"相关视频"画面露出来
- 播放器缓冲时，舞台灯光保持、指挥"停顿"，不要让乐团在没有声音时继续演
- 官方频道的片段**可能插播广告**，前端没有可靠的方法检测或跳过。播放器状态异常时用幕布盖住巨幕，
  乐团进入等待姿态；想要零打断的体验，就用本地模式

## Cue 时间表

每首歌一个文件 `src/cues/<slug>.js`，导出按时间排序的数组，每项 `{ t: 秒, name, intensity, events[] }`。
主循环每帧取当前播放时间，找到最近一个已经过的 cue，平滑插值 `intensity`，
并触发一次性事件（如 `flash`、`shake`、`drumHit`）。

> 时间点需要对照视频人工标注，这是作品"节奏感"的来源。
> 初版可以粗略一些（按曲子的大段落来标），每个 cue 都加注释，方便之后微调。

## 技术栈

- 纯静态站点：Vite + Three.js（npm），构建产物部署到 GitHub Pages
- 不需要后端
- 目标：桌面 Chrome/Safari 60fps；移动端降级（关 bloom、减少粒子）

## 非目标（YAGNI）

- 不做用户账号、评论、多首曲目切换
- 不做 VR
